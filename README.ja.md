# Agentic Router Proxy

> **ドラフト — リリース前に確定予定。**

[English](README.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · [简体中文](README.zh-CN.md)

Agentic Router Proxy は Claude Code 向けの難易度ベースのチームルーターです。プラグインとローカル
デーモンが各リクエストを読み取って難易度を見積もり、メインセッションに直接処理させるか、リクエストに
合った規模のサブエージェントチーム（architect, coder, reviewer, tester, ui-designer）を編成します。各
ロールはモデル × effort の「はしご」に乗り、作業が難しければ上がり、簡単なら下がって、検証を通る範囲で
最も低いコストで作業を終えることを目指します。CLI とパッケージの名前は `agentic-router` です。

**仕組み。** Claude Code プラグインはフックイベントを `127.0.0.1` のローカルデーモンへ転送します。
デーモンは各リクエストを判定し、計画と作業台帳を 1 つのローカル SQLite ファイルに記録し、メインセッション
（「リード」）に対して自分で処理するか委任するかを伝えるブリーフを注入します。委任する場合、リードは
プラグインが強制する書き込みスコープとともにサブエージェントを呼び出し、デーモンは各サブタスクのビルド・
型チェック・lint・テストを実行してコストを記録し、ロールをはしご上で調整します。記録・助言のためのフックは
失敗時に素通りします。デーモンが動いていなければ、Claude Code はプラグインがないときと同じように動作し、
その作業は「未検証」として記録されます。サブエージェント向けの書き込みスコープガードはローカルファイルで
動作し、エラー時はブロックするため、サブエージェントが自分のスコープ外に書き込むことはありません。

## 判定

ステージ 1 はルールのみ — 埋め込みも追加のモデル呼び出しもありません。ルールで規模を判断できないときだけ
ステージ 2 に進みます。**サブスク** モードではリードがコンテキストに注入されたルーブリックで判断し、
**API キー** モードでは Sonnet 5.5 の judge 呼び出し（effort medium）があなたの API キーで実行されます。
埋め込みによる類似事例検索は現時点では保留しています。

## 委任とはしご

どのレベルを委任するかはリード（メインセッション）のモデルによって決まります。Opus 級または Sonnet の
リードは **L1** から、Haiku または不明のリードは **L2** から委任し、**L0** は常に直接処理します。委任が
割に合うのは、高価なリードが自ら編集をしなくなるからです。直接対チームの実測では、リード + Haiku coder
1 名はリード単独より約 40% 安くなりました（`docs/measurements/` を参照）。

ロールは 2 回連続のミス、2 回の reject、またはリードが要求したときに 1 段 **上がります**。リードの要求は
モデルが変わらなければスロットごとに 1 回は確認なしで、それ以外はユーザーの確認後に適用されます。1 つの
スロットは最大 3 回まで上げられ、その後はユーザーに尋ねます。ロールはレビュアーまたはテスターが「easy」と
判定した結果が 2 回連続したときに 1 段 **下がります**。

## インストール（リリース前, ソースから）

まだ npm には公開していません。クローンから実行してください:

```
git clone <repo> && cd agentic-router
npm ci
node packages/cli/src/index.ts <command>      # pre-release entry point
```

以下では `agentic-router <command>` はこの実行エントリを指します。要件: **Node 24+**, **Claude Code
≥ 2.1.295**, そして **Windows では Git Bash**。

- `agentic-router init` — Claude Code プラグイン（ロール, フック, リードスキル, ルーター MCP ツール）と
  ステータスラインを登録し、サブスクモード（既定）に設定します。API キーモードは `init --mode api` を
  使います。
- `agentic-router start` — ローカルデーモン（判定 API, 作業台帳, ダッシュボード）をバックグラウンドで
  起動します。
- `agentic-router doctor` — 設定を点検し、問題を報告します。
- `agentic-router status` / `stop` — デーモンの状態を表示する／停止します。
- `agentic-router dashboard [--no-open]` — ローカルダッシュボードを開きます（下記参照）。
- `agentic-router mode subscription|api|direct|proxy` — モードを切り替えます（モード参照）。
- `agentic-router policy show|accept|revoke` — プロジェクトの `.agentic-router/policy.json` を確認し
  受け入れます（ルーターワーカーの権限参照）。
- `agentic-router data export|purge`, `agentic-router routing reset` — ローカルデータを書き出す／消去し、
  学習したルーティングをリセットします。
- `agentic-router uninstall [--keep-key]` — 先に確認したうえで、プラグインの設定項目、プロジェクトの
  `worktree.baseRef` と `.gitignore` の行、設定バックアップとキーチェーンのキーを削除し、デーモンを停止
  します。データフォルダは残ります。
- API キーモード専用: `agentic-router token rotate [--no-grace]`, `agentic-router key set`,
  `agentic-router proxy allow-upstream <https origin>`。

## モード

- **サブスク**（既定, `init`）: プラグインとローカルデーモンだけで動作します。プロキシはなく、どの
  コンポーネントもサブスクリプションの資格情報を読み書きしません。トラフィックは Claude Code から
  Anthropic へ直接送られます。
- **API キー**（`init --mode api`）: オプトインのローカルプロキシが実トークンコストを集計し、ローカル
  トークンごとに 1 日 $100・合計 1 日 $300 の上限（設定可能）とリクエストごとの予算を適用します。上限を
  超えると、プロキシは新しい呼び出しを 429 で拒否し、進行中の応答は中断しません。API キーは OS の
  キーチェーン（Windows 資格情報マネージャー / macOS キーチェーン / Linux libsecret）にのみ保存されます。
- **ダイレクト（direct）**: プロキシに問題が起きたときは、`agentic-router mode direct` でプロキシを
  経由せず API キーで直接接続し、`agentic-router mode proxy` で戻します。

いつでも `agentic-router mode subscription|api|direct|proxy` で切り替えられます。

## ダッシュボード

`agentic-router dashboard` は読み取り専用のローカル Web ダッシュボード（デーモンが `127.0.0.1` で提供）を
開きます。リクエストのタイムライン、各リクエストのチーム・ステップ・検証結果、コスト（リード対ワーカー）、
KPI、判定対実績の学習レポート、自動解除パネルを表示します。英語・韓国語・日本語・簡体字中国語に対応し、
すべてのデータはこの端末内に留まります。

## プライバシー

すべては 1 つのローカル SQLite ファイルに保存されます。Claude Code 自体のトラフィックと、API キーモードに
限りステージ 2 の judge の Anthropic への呼び出し以外は、何も端末の外に出ません。学習ストアにはルールから
抽出した特徴量、結果、コスト、類似度などの数値を保存し、埋め込みは保存せず、プロンプト本文は
`recordPrompts` を有効にしたときだけ保存します。`recordPrompts` をオフにすると、保存済みのプロンプト本文は
次回のデーモン起動時に削除されます。ログとダッシュボードは API キーとトークンをマスクします。どの
コンポーネントもサブスクリプションの資格情報を読み書きしません。

## 自動解除のホールドアウト

委任が今も割に合うかを確認するため、委任レベルのリクエストのおよそ 10 分の 1 をあえてリードが直接処理し、
ホールドアウトの基準とします。既定は **observe** です。ホールドアウトは動作し、ダッシュボードは比較と解除
した場合の結果を表示しますが、`autoRelease` をオンにするまで何も切り替わりません。ホールドアウトを取るのを
やめるには、`holdoutRate` を `0` にするか、`autoRelease` をオフにします。

## ルーターワーカーの権限

ルーターのワーカー（リードが送る coder・tester などのサブエージェント）は、ほかのエージェントと同じように
Claude Code のツールを使います。ルーターはそれらのツールの前にガードを置き、ガードは次の 3 つのいずれかで
答えます:

| ガードの答え | いつ | 結果 |
|---|---|---|
| 拒否 | 許可されない呼び出しと認識されたとき: サブタスクのスコープ外への書き込み、資格情報ファイル、ルーター自身のフォルダ、ワーカー許可リストにないコマンドやオプション。 | 呼び出しは実行されません。どの許可ルールもこれを上書きできません。 |
| 許可 | リポジトリ内で名前を指定したファイルの読み取りや検索、そしてサブタスクのスコープ内のファイル編集。 | 確認なしで実行されます。 |
| 沈黙 | 拒否しなかったすべての Bash コマンド。 | ルーターがないときと同じく、Claude Code 自身の権限ルールが決めます。 |

### Bash はあなたの権限ルールを通ります

ガードはコマンドラインを読むだけで、サンドボックスには入れません。だからあなたの代わりに Bash コマンドを
承認することはありません。ワーカーの `npm test` や `npm run build` は、Claude Code のほかの Bash コマンドと
同じように扱われます。ルールが許可すれば実行され、そうでなければあなたに尋ねます。非対話実行（`claude -p`）
では尋ねる相手がいないため、許可ルールのないコマンドは拒否されます。

ワーカーに確認なしでビルド・テストをさせるには、それらのコマンドを許可します:

```
claude --allowedTools "Bash(npm test)" "Bash(npm run *)"
```

または `.claude/settings.json` で:

```json
{ "permissions": { "allow": ["Bash(npm test)", "Bash(npm run *)"] } }
```

スクリプトを 1 つだけ許可するには、`"Bash(npm run *)"` の代わりに `"Bash(npm run build)"` を使います。
ほかのツールチェーンは、そのテスト・ビルドコマンドを同じやり方で許可してください。

ルールを追加する前に知っておくこと:

- **連結コマンドは各部分すべてを許可する必要があります。** Claude Code はコマンドを `&&`, `||`, `;`, `|`
  で分割し、各部分を個別に確認するため、`Bash(npm test)` だけでは `make && npm test` をカバーできません。
  作業ツリー内のディレクトリへ入る `cd` は読み取り専用でルールが不要なので、`cd packages/web && npm test`
  には `npm test` のルールだけで十分です。
- **ルールはセッション全体に適用されます。** リードとすべてのワーカーに適用され、ルーターワーカーだけに
  限りません。
- **コードを実行するコマンドを許可することは、そのコードを保証することです。** テストファイルやパッケージ
  スクリプトはプログラムです。いったん許可すると、あなたの権限で、あなたのファイルアクセス権で実行されます。
  ルーターは `package.json` の `scripts` が最後のコミットと異なるとき、あなたまたはリードが確認するまで
  パッケージスクリプトとインストールを拒否しますが、テストやスクリプトが何をするかは調べません。
- **拒否は許可ルールに勝ちます。** `"Bash(npm run *)"` を許可しても、`npm run env`（環境を出力）はやはり
  拒否されます。`"Bash(cat *)"` を許可しても、`cat .env` はやはり拒否されます。

### 何を許可してもワーカーができないこと

- サブタスクのスコープ（`[scope: ...]`）外への書き込み、または CI 設定、`.claude/`, `.git/`, `.mcp.json`,
  `.husky/`, `CLAUDE.md` など、リポジトリやエージェントの動作を変えるファイルへの書き込み。
- 資格情報ファイル（`.env`, `.npmrc`, `~/.ssh`, `~/.aws` など）やルーターのフォルダ
  （`~/.agentic-router`）の読み取り・検索・一覧。`.env.example` などのテンプレートは読み取れます。
- ワーカー許可リスト外のコマンド（ネットワークツール、シェル、インラインコードを実行するインタプリタ）の
  実行、環境の出力、秘密らしい変数の参照。
- ガードが追えないシェル構文の使用: `$'…'` 文字列、`${VAR}` 展開、コマンド置換、コメント、ファイルへの
  出力リダイレクト。
- レジストリ以外からのパッケージインストール（URL、git スペック、`user/repo` 省略形は不可）。
- PowerShell の使用。ワーカーは Bash のみを使います。

正直に作業しているワーカーでも、一部の拒否に戸惑うことがあります。メッセージが代わりの方法を示します:

| 拒否 | 代わりに |
|---|---|
| `rg --hidden`, `rg --no-ignore` | それらを付けない `rg`、またはファイルを指定 |
| `git diff --no-index` | 追跡対象ファイルへの `git diff`、または `diff` |
| `printf -v`, `echo ${VAR}` | ふつうの `printf` / `echo $VAR`（秘密でない名前） |
| コマンド内のコメント | コメントを削除 |
| `npm install user/repo` | レジストリ名; それ以外はリードに依頼 |
| 無視されない `.env` を含むディレクトリ全体の grep | glob や type を追加、サブディレクトリを検索、またはそのファイルを `.gitignore` に追加 |

### プロジェクトポリシー

リポジトリは `.agentic-router/policy.json` でワーカー許可リスト（`bashAllow`）を拡張し、検証に渡す環境
変数（`verifyEnv`）を指定できます。このファイルは、あなたが受け入れたあとにのみ有効になります:

```
agentic-router policy show
agentic-router policy accept
```

受け入れはファイルの内容に結び付きます。たとえば `git pull` のあとなどファイルが変わると、新しい内容を
受け入れるまで再び無視されます。`agentic-router doctor` が現在の状態を表示します。

### ワーカーにはデーモンが必要です

ワーカーは、ルーターに自分のスコープ記録があるときだけ書き込めます。その記録は、リードがワーカーを送る
ときにデーモンが書きます。デーモンが動いていなければ、ルーターワーカーはファイルを編集できませんが、
読み取りはできます。`agentic-router status` がデーモンの稼働状況を表示します。

## 限界

- verify は関連するビルド・型チェック・lint・テストを実行するため、それらのチェックが拾わない形で誤った
  修正は通過することがあります。
- 「受容」は異議が観測されなかったこと（取り消し・再依頼・苦情がない）を意味するため、成功/受容率は測定
  された承認率ではなく **上限値** です。
- 自動解除は大きな損失を防ぐブレーキであり、細かな最適化の道具ではありません。チームが明らかにもう安く
  なくなったときに、広いバンドの範囲でそのレベルを直接処理へ戻します。
