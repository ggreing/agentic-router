# Agentic Router Proxy

[English](README.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · [简体中文](README.zh-CN.md)

Claude Code を Opus や Sonnet で動かすと、メインセッションがほとんどの作業を自分でこなします。ずっと
安いモデルでも問題なく直せるような修正まで全部です。このプロジェクトは、それを変えるための Claude Code
プラグインと小さなローカルデーモンです。リクエストごとに、メインセッションがそのまま処理するか、安い
モデルで動くサブエージェント数体に作業を渡してメインセッションは計画と確認に回るかを決めます。

最後に確かめたときは、Sonnet のメインセッションでルーターを配布状態のまま有効にしておくと、通過した
タスク 1 件あたりのコストが、素の Claude Code より 33% 少なくなり、通過したタスクも同じでした。多くは
メインセッションが Haiku のコーダー 1 体に修正を渡す形でした。その代わり遅くなります。渡すたびにワーカー
を新しく起動する必要があり、大きいタスクではチームのほうがメインセッション 1 つより目に見えて時間が
かかりました。数値と測り方は [docs/measurements](docs/measurements/) にあります。

CLI とパッケージの名前は `agentic-router` です。

## 仕組み

プラグインは Claude Code のフックイベントを `127.0.0.1` のデーモンへ転送します。プロンプトを送ると、
デーモンはモデルを呼ばずにルールだけでリクエストの大きさを見積もり、メインセッション（ここでは「リード」
と呼びます）に、自分で処理するかチームに任せるかを伝えます。

タイポや 1 行の修正のような小さなものはリードがそのままやります。それより大きいものは、リードが Opus 級か
Sonnet のとき、あるいはどのモデルか判別できないときに、チームへ任せます。リードが Haiku のときは L1 程度
は自分でやります。どうせワーカーも同じモデルで動くので、渡しても得がないからです。ルールでは大きさを
判断しづらいリクエストは小さなチームに回し、どの役割が実際に要るかはリードが選びます（Haiku のリードには
短い判断基準が渡され、自分で決めます）。

ワーカーは、たいてい通る一番安い段から始まり（コーダーなら Haiku、effort low）、失敗すると上がります。
2 回続けて外す、レビュアーかテスターに 2 回却下される、あるいはリードが要求する、のいずれかで 1 段上げ
ます。逆にレビュアーから「余裕あり」の判定が続くと 1 段下がります。3 回上げても駄目ならユーザーに尋ねます。

ワーカーが終わると、デーモンはその作業ツリーでプロジェクトのビルド・型チェック・lint・テストを回し、
ワーカーが渡された範囲のファイルだけを触ったかを確認します。何を計画し、実際にどうなり、いくらかかったか
は、すべてローカルの SQLite ファイル 1 つに残ります。

デーモンが動いていなければ、Claude Code はプラグインが無いときと同じように振る舞います。例外はルーターの
ワーカーで、デーモンが動いているときしか書き込めないので、担当範囲の外を触ってしまうことはありません。

## はじめに

まだ npm には出していません。Node 24 以上、Claude Code 2.1.295 以降が必要で、Windows なら Git Bash も
要ります。

```
git clone https://github.com/ggreing/agentic-router && cd agentic-router
npm ci
npm run build:dashboard
node packages/cli/src/index.ts init
node packages/cli/src/index.ts start
```

パッケージを公開するまでは `node packages/cli/src/index.ts` が CLI で、以下では `agentic-router` と略します。
`init` はプラグインとステータスラインを登録しますが、Claude Code の設定を変える前に確認を取ります。うまく
いかないときは `agentic-router doctor` でセットアップを点検してください。

よく使うコマンドはこのあたりです。

| コマンド | 何をするか |
|---|---|
| `status`, `stop` | デーモンの状態を見る、止める |
| `dashboard` | ローカルダッシュボードを開く |
| `mode subscription\|api\|direct\|proxy` | モードを切り替える（下記） |
| `policy show\|accept` | プロジェクトの `.agentic-router/policy.json` を確認してから適用する |
| `data export`, `data purge` | ルーターが記録した内容を書き出す、消す |
| `uninstall` | `init` がしたことを元に戻す（データフォルダは残る） |

## サブスクリプションか API キーか

既定ではあなたの Claude サブスクリプションで動きます。このモードにはプロキシが無く、ルーターはサブスク
リプションの資格情報を読むことも保存することもありません。Claude Code はこれまでどおり Anthropic と直接
やり取りします。

API キーで使うには `agentic-router init --mode api` を実行します。API の手前に小さなローカルプロキシが
入り、呼び出しごとに実際のトークンコストを記録し、1 日の予算を適用します。既定ではローカルトークンごとに
1 日 $100、合計で 1 日 $300 です。各リクエストは最悪のケース（プロンプトの大きさと `max_tokens` をその
モデルの最高レートで見積もった値）をこの上限に対して確保し、リクエストが終わるまで保持します。その分が
収まらなければリクエストを始めません。とはいえこの確保が覆うのはリクエスト本文だけです。API が自分で取り
込むもの（ID で参照したファイル、URL で参照した画像、ウェブ検索などのサーバーツール）は本文に無く、呼び
出しが精算されるときに課金されるので、1 日が上限を少し超えて終わることがあります。キー自体は OS の
キーチェーンにだけ置きます。プロキシが邪魔なときは
`agentic-router mode direct` で迂回し、`agentic-router mode proxy` で戻せます。

**ローカル TLS。** API キーモードでは Claude Code は `https://127.0.0.1:<port>` でプロキシに接続し、この
ルーターだけが持つ証明書を使います。`openssl` で作り、`127.0.0.1` と `localhost` にのみ有効で、ほかのサイト
の保証はできず、ルーターホームにあなただけが読める形で置きます。Claude Code は設定の `NODE_EXTRA_CA_CERTS`
を通じてこの証明書を信頼します。証明書は期限が切れる前に更新され、更新中に開いていた Claude Code のセッション
は再起動が必要です。`doctor` がそのタイミングを伝えます。別のプログラムがプロキシの停止中にそのポートを奪っても
TLS ハンドシェイクを完了できないので、ローカルトークンもプロンプトもそこには届きません。すでに
`NODE_EXTRA_CA_CERTS` を自分で設定している場合（たとえば社内 CA）、ルーターはあなたの証明書と自分の証明書を
束ねたバンドルを Claude Code の設定に書き込み、社内 CA も信頼されたままにします。`mode direct`・
`mode subscription`・`uninstall` はあなたの元の値に戻し、`doctor` はシェル変数もそのバンドルを指すよう勧め
ます。`openssl` が無ければプロキシは同じリクエスト点検を保ったまま平文 HTTP で動き、`doctor` がそれを伝え
ます。

**社内プロキシの背後で。** プロキシは環境が指定するプロキシ経由で API に届きます。`https_proxy`、
`HTTPS_PROXY`、`http_proxy`、`HTTP_PROXY` のうち最初に設定されたもの（Claude Code が使う順）を用い、
`NO_PROXY` を尊重します。Node 組み込みのプロキシ対応（Node 24.5 以降）を使うので、HTTPS は CONNECT
トンネルを通り、API の証明書は端から端まで検証されます。プロキシ URL に含まれる資格情報はプロキシにしか
渡らず、ログ・エラー・`doctor` には現れません。TLS を覗くプロキシの場合、そのルート証明書を Node が信頼
する必要があり、たとえば `NODE_EXTRA_CA_CERTS` で指定します。SOCKS には対応せず、ルーターが使えない
プロキシ設定なら、こっそり迂回する代わりに起動を止めます。

逆方向では、そのままだと Claude Code が `127.0.0.1:<port>` のローカルプロキシ宛てに送る自分のリクエスト
（ローカルトークンを含む）も社内プロキシを経由してしまいます。そこでプロキシが設定されていると、
`agentic-router init --mode api` と `mode api` が Claude Code の設定の `NO_PROXY` に `127.0.0.1` と
`localhost` を追加し（既存の項目は残します）、`mode direct`・`mode subscription`・`uninstall` は自分が
追加した分だけを取り除きます。`agentic-router doctor` は両方向を確認します。

## ワーカーと権限

ルーターのワーカーは Claude Code の通常のツールを、ガードを挟んで使います。ガードは担当範囲の外への
書き込み、資格情報ファイルやルーター自身のフォルダに触れること、小さな許可リストの外のコマンドを拒否
します。ただし Bash をあなたの代わりに許可することはしません。ワーカーの `npm test` も、普段の Claude
Code の権限ルールを通ります。ワーカーが毎回聞かれずにビルドとテストを回せるようにするには、こう許可して
おきます。

```
claude --allowedTools "Bash(npm test)" "Bash(npm run *)"
```

何がなぜ拒否されるか、その全一覧は [docs/worker-permissions.md](docs/worker-permissions.md) にあります（英語）。

## データ

記録はすべて自分のマシンの SQLite ファイル 1 つに残り、ルーターが自分から外部へ通信することはありません。
既定ではプロンプトやワーカーの報告内容は残さず、ID・サイズ・結果・コストだけを残します。あとで分析する
ためにプロンプトを残したいときは `recordPrompts` を on にします。また off にすると、次にデーモンが起動
したときに保存したプロンプトを消します。イベントの記録は 30 日間保ちます。

## ダッシュボード

`agentic-router dashboard` を実行すると、デーモンが出す読み取り専用のページが開きます。最近のリクエスト、
誰が何をしたか、どの検査を通ったか、コスト（リードとワーカー）、そしてリクエストの大きさについてのルーター
の最初の見立てがどれだけ当たったかを見られます。英語・韓国語・日本語・簡体字中国語に対応しています。

## 委任が今も得かを確かめる

本来ならチームに回すリクエストの 10 件に 1 件ほどを、わざとリードに直接やらせて、比べる相手を作ります。
既定では比較の結果を見せるだけで、`autoRelease` を on にしない限り、自分から何かを止めることはありません。
比較そのものが要らなければ `holdoutRate` を 0 にしてください。

## まだうまくいかないこと

ワーカーが終わったあとに回す検査は、結局そのプロジェクトのテストです。テストが見ない形で間違っている修正
は通ってしまいます。そのときリードが作業を 1 段上へ戻すことはできますが、まず気づく必要があります。

ダッシュボードの「受容」は、続く数個のプロンプトの間に変更を取り消したり、同じ依頼をやり直したり、苦情を
言ったりしなかった、という意味です。作業が実際に良かったかを測った値ではなく、良かったかもしれない割合の
上限です。

自動の切り替えは、委任が明らかに割高になった場合を捕まえるためのもので、細かく調整するものではありません。
扱う標本の大きさでは、25% ほどの損失を偶然と区別できません。

まだ正式リリース前なので、コマンドや既定値は変わることがあります。
